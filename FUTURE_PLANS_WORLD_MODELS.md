## 1. Verdict From the Critical Review

**Conditionally viable.** The architecture and paper stack are sound. The original
implementation reference had one fatal blind spot and three serious flaws, all fixed
in this document by reordering the plan around hard go/no-go gates.

| Severity | Finding | Fix in this plan |
|---|---|---|
| **FATAL** | The repo contains **zero real weld data**. All 10 "sessions" are generated by `backend/data/mock_sessions.py`. The only session files are `data/mock/session_001.json` / `session_002.json`. The original plan's "sim-to-real fine-tune" was actually sim-to-sim: calibrating the Goldak simulator against another simulator. The world model would have been a learned imitation of our own mock generator. | Gate 0 (real data collection) is now the first milestone, before any world-model code. |
| SERIOUS | The physics loss as drafted was decorative: penalising one latent dim for violating heat balance does not force the network to *use* that dim for thermal state — gradient descent routes real thermal info through the unconstrained dims and the constraint goes to zero without constraining anything. | Structured latent: `z = [z_phys(4) ‖ z_free(28)]`. The heat-dissipation channel is decoded **exclusively** from `z_phys` (architecturally separate head). Physics residual applies to `z_phys`. Thermal information is forced through the constrained block. |
| SERIOUS | Fusion-depth validation gate was circular: model trained on Goldak output, validated against Goldak output. Passing proves the model inverts its own training data — nothing about real welds. | Gate 5: no millimetre figure is shown in any UI until validated against ≥10 physically sectioned coupons. Until then, qualitative risk bands only. |
| SERIOUS | No boring baseline. A plain supervised GRU/1D-CNN on raw frames (3 days of work) might match the entire Latent-ODE/VQ-VAE apparatus. | Gate 3: world model must beat the GRU baseline on held-out synthetic data, or we ship the GRU and defer the world model. |
| MINOR | KL balancing (DreamerV3 trick) requires a *learned* prior; the Latent ODE uses fixed N(0,I) — nothing to balance. | Dropped. Keep symlog, free nats, percentile norm. |
| MINOR | Dual-encoder incoherence: ODE-RNN (offline) and VQ-VAE tokenizer (streaming) produce incompatible latent spaces but were drawn feeding the same dynamics model. | MVP is post-session only (ODE-RNN). Streaming tokenizer is Phase 2, distilled from the trained world model (teacher–student), not co-trained. |
| MINOR | `dopri5` through a 1,500-frame encode threatens the 500ms p95 latency gate. | Fixed-step `rk4` at inference; adaptive solver for training only. |
| MINOR | Rosenthal quasi-steady fusion-depth solution is least accurate at **stitch transitions** — exactly where LOF forms (our own `heat_input_drop_severity` feature targets this). | Gate 1 explicitly tests direction-of-change at transients. If Rosenthal fails it, upgrade to transient FEM (FEniCS) before generating training data. |
| CONTEXT | PHOENIX's 98% used melt-pool *imaging* (thousands of pixels of direct observation). We have 4 scalar channels. Their ceiling does not transfer to us. | Gate 1.5 measures our actual observability ceiling before we commit months. |

## 2. The Vision (One Paragraph)

The thing that determines whether a weld holds — fusion zone depth — cannot be
measured by any surface sensor. The current pipeline infers a verdict from 11
summary statistics after the weld is done. The world model maintains a live,
physics-constrained estimate of the **internal weld state** at every moment of the
pass, reconstructs *where and when* fusion failed, quantifies its own uncertainty,
and (eventually) simulates counterfactuals ("what if the angle had been corrected at
second 7?"). The existing FNR = 0.000 threshold-based safety override is never
replaced — the world model runs alongside it as a second, deeper opinion.

## 3. Data Strategy — Three Layers, Not Interchangeable

The original plan conflated three different kinds of data. Each de-risks a
different thing; none substitutes for another.

### Layer 1 — Public real datasets (breadth + sensor realism). Use now.

These prove the pipeline learns from *real* electrical signals and teach the encoder
what real arc noise looks like (mock data is too clean). They **do not** pass
Gate 0: none has our channels (`heat_dissipation_rate`, `angle_degrees`), our
process (aluminium MIG stitch), or any paired penetration-depth ground truth.

| Dataset | Size | What it has | Access | Use for |
|---|---|---|---|---|
| [SmartData@Polito RSW](https://github.com/smartdatapolito/resistance_spot_welding_dataset) | 1,976 labelled samples | V / I / force / displacement time series, fault labels | Open | Encoder pre-training on real electrical dynamics; real-noise statistics |
| [Intel Robotic Welding Multimodal](https://huggingface.co/datasets/IntelLabs/Intel_Robotic_Welding_Multimodal_Dataset) | 4,000+ samples | GMAW arc — CURRENT_A, VOLTAGE_V time series + audio/video/images, 12 defect classes | Gated — request access (days) | Closest public match to our process (arc GMAW); pre-training + defect taxonomy |
| [Bacioiu TIG SS304](https://www.kaggle.com/datasets/danielbacioiu/tig-stainless-steel-304) | 45,058 images / 56 runs | HDR weld-pool images, 6 classes incl. LOF & LOP | Open | Label taxonomy reference only (images, not sensor streams) |
| [Kaggle welding V/I time series](https://www.kaggle.com/datasets/thunder7/welding-current-and-voltage-time-series-data) | Small | Arc V/I streams, no labels | Open | Minor — extra pre-training noise |
| [Void formation FSW](https://www.kaggle.com/datasets/arindambaruah/void-formation-process-data-in-welding) | 108 entries | Process params → void labels | Open | Minor — defect framing reference |

### Layer 2 — Our own real data (the anchor). **This is Gate 0. Nothing substitutes.**

- **≥30 real ESP32 sessions** on physical aluminium welds through the existing
  `POST /sessions` API. Weld matrix: ~10 nominal, ~5 deliberately cold (low current),
  ~5 off-angle, ~5 fast-travel, ~5 stitch-restart abuse.
- **≥8 coupons sectioned and etched**, penetration depth measured. For aluminium:
  bandsaw cut, polish, ~10% NaOH etch, measure with calipers/macro photo. Roughly
  $200 in materials. If no shop access: university lab, makerspace, welding school,
  or pay a certified inspection shop for macro sections.
- **Bench-verify the heat-dissipation channel** on real hardware (in mock data it is
  *computed* from simulated temperatures — confirm the real sensor path produces a
  usable signal at all).

**Why synthetic data can never pass Gate 0:** Gate 0 exists to provide the reality
anchor that synthetic data is validated *against*. Synthesising data to validate
synthetic data is the exact circularity that made the original plan fatal. Synthetic
is the **amplifier** (Layer 3); real is the **anchor** (Layer 2). Both required,
never interchangeable.

### Layer 3 — Goldak synthetic corpus (volume + hidden-state labels). Only after Gate 1.

5,000 sessions with per-frame `fusion_zone_depth` ground truth, defect injection
(LOF = cold window, LOP = angle + power deficit), domain randomisation over material
properties, ambient temperature, CTWD, travel speed, plate thickness, sensor noise.
Without domain randomisation the model overfits the simulator manifold and transfer
fails silently.

## 4. Go/No-Go Gates

**Meta-rules:**
1. Kill criteria are written *before* running the experiment and never moved after
   seeing data.
2. Failing a gate is a result, not a setback — it gets documented in the README like
   every other measured decision in this project.
3. No component advances on "it should work." It advances on a number.

| Gate | Blocks | Pass criteria | Kill criterion |
|---|---|---|---|
| **0 — Reality** | all world-model code | ≥30 real ESP32 sessions (incl. deliberate defects); ≥8 sectioned coupons with measured penetration; heat-diss channel verified on hardware | Real sensor stats look nothing like mock → the *existing* classifier results are also invalid; re-baseline the whole project first |
| **0.5 — Public-data pre-training** (optional accelerator, parallel with 0) | nothing — runs in parallel | Encoder pre-trained on Polito + Intel data; VQ/encoder reconstruction works on real signals; codebook ≥60% utilisation on real data | Pipeline can't learn real electrical dynamics → architecture problem exposed early, fix before our own data arrives |
| **1 — Simulator validity** | generating the 5,000-session corpus | Goldak predicts coupon penetration within ±25%; direction-of-change correct (↑I→↑depth, ↑speed→↓depth, stitch restart→↓depth); sensor moments match **real** sessions within ~15% | Simulator wrong on transient direction-of-change → synthetic fusion labels are noise; upgrade to transient FEM or stop |
| **1.5 — Observability ceiling** | committing to the architecture | Oracle regressor (4 sim channels → sim fusion depth) achieves ≤ ~1.0mm irreducible error inside the simulator | Ceiling > 1mm → 4 channels are physically insufficient; add sensing (the 5×5 thermal snapshot array already in the data model) before any modelling. Two days of work that can save four months |
| **2 — Representation** | training the full world model | VQ codebook ≥60% utilisation; linear probe latent→11 features beats mean baseline; probe latent→quality ≥ GBDT on synthetic held-out | Latent loses to hand-engineered features → representation adds nothing |
| **3 — Earn the complexity** | backend integration | World model ≥ plain supervised GRU on held-out synthetic (quality F1 **and** fusion MAE); counterfactuals monotonic (≥95% of sampled pairs: ↑V·I→↑depth, ↑speed→↓depth, ↑angle dev→↓depth); physics-loss ablation shows measurable OOD effect | GRU matches it → ship the GRU as MVP, defer world model. Ablation shows nothing → physics term decorative; fix grounding before proceeding |
| **4 — Transfer** | trusting outputs on real welds | Feature-decoder R² ≥ 0.5 on real sessions; latent KL synthetic↔real < 0.5 nats; reconstruction ≤ 2× synthetic error | Encoder can't predict real engineered features better than mean-prediction → no transfer happened |
| **5 — Fusion truth** | showing any mm figure in UI | MAE ≤ 1.0mm vs macro sections on a **fresh** ≥10 coupons; direction-of-change correct ≥90% | Until passed: UI shows qualitative risk bands only. A wrong-but-precise number in front of a quality engineer is the most dangerous output this system can produce |
| **6 — Deployment** | influencing any disposition | 2–4 weeks shadow mode with all disagreements manually reviewed; FNR = 0.000 on expanded eval (24 scenarios + synthetic FN_RISK suite — note 0/24 alone has a ~12% binomial 95% CI upper bound); OOD detector wired (non-aluminium/non-MIG inputs get flagged, not predicted); p95 ≤ 500ms with rk4 | Any missed defect in shadow mode → not deployable, full stop |
| **7 — Edge viability** (Workstream S, §11) | claiming on-device inference | distilled int8/int4 student within Δ of teacher (quality F1 **and** fusion MAE) at the ESP32-S3 ms + mJ/inference budget | student loses > Δ on the LOF class at every MCU-fitting size → on-device LOF detection not viable; ship streaming server-side, document it |

## 6. Architecture (Corrected MVP)

Post-session analysis only. Streaming is Phase 2.

```
ESP32 stream [4ch × 1500 frames]
        │
ODE-RNN Encoder (Rubanova 2019)
  backward GRU pass, ODE step between frames
        │
  z_0 ~ N(μ₀, σ₀) ∈ R³²,  structured: z = [z_phys(4) ‖ z_free(28)]
        │
Neural ODE dynamics  dz/dt = f_θ(z,t)   (Chen 2018, MLP 32→64→64→32 tanh)
  + physics residual on z_phys: dT/dt = Q/(ρ·cp·V) − k(T − T_amb)   (Raissi 2019)
        │
  z_t for all t ∈ [0, T]
        │
  ├── Sensor decoder        heat_diss decoded ONLY from z_phys (grounding);
  │                          volts/amps/angle from full z       → L_recon (all data)
  ├── Quality decoder       concat(z_T, 11 engineered features) → P(GOOD/MARG/DEF)
  │                          (PHOENIX feature-level fusion)      → L_quality (labelled)
  ├── Fusion-depth decoder  MLP(z_T) → depth_mm                  → L_fusion (synthetic)
  └── Feature decoder       MLP(z_T) → 11 SessionFeatures        → L_aux (all data, free
                             supervision from the existing extractor — no labels needed)
```

Loss schedule (progressive fading, PINN 2025):
`L_recon` always on · `L_aux` fades in ep 0–100 · `L_physics` ep 50–150 ·
`L_quality` ep 150–250 · `+0.001·L_KL` (free nats = 1.0) always on.
All reconstruction targets in symlog space.

## 9. Anti-Fluff Charter

How we guarantee this project stays real:

1. **Pre-registered kill criteria.** Every gate's failure condition is written in
   this file *before* the experiment runs, and never edited afterward. If a gate
   fails, the failure is documented and the plan changes — visibly.
2. **The boring-baseline rule.** Every complex component must beat its boring
   alternative on a held-out set, with the decision threshold declared in advance
   (the existing README already does this — e.g. "P@6 < 0.70 → build hybrid").
   If the GRU wins, the GRU ships and the README says so.
3. **One physical artifact beats ten synthetic metrics.** The project's flagship
   evidence is a photo of a sectioned weld next to the model's predicted fusion
   depth with measured-vs-predicted numbers. Fluff projects have dashboards; real
   projects have validation artifacts.
4. **Negative results go in the README.** "We tried X, it failed Gate Y at Z, we
   did W instead" is what makes the work credible to senior engineers and reviewers.
5. **No millimetres before Gate 5. No dispositions before Gate 6.** Uncalibrated
   precision shown to a quality engineer is worse than nothing.
6. **Don't call it a world model until it earns the name.** The capability that
   justifies the term is validated counterfactual reasoning (Gate 3's monotonicity
   battery passed, and later, counterfactuals spot-checked against the simulator and
   coupons). Until then it is a "physics-informed latent state estimator" — which is
   already a strong, honest claim.
7. **The safety floor is non-negotiable.** The deterministic threshold override
   stays below every learned component, exactly as it sits below the LLM layer
   today. FNR = 0.000 gates everything.

## 11. Workstream S — Edge Inference & Systems Co-Design (added 2026-06-16)

A systems-engineering workstream over the model plan — quantization, a custom kernel,
explicit distillation, a production serving stack, inference co-design, an upstream PR,
and a scaling study. Full detail in `WORLD_MODEL_IMPLEMENTATION_REFERENCE.md` **PART J**.

Two rules keep it consistent with this plan's spine:

1. **Two inference targets, not one.** The MVP world model is **server-side**
   (post-session); the on-ESP32 target is the **distilled streaming student** (Paper 5),
   not the teacher. Quantization / MCU kernel / co-design live on the student; the
   serving stack wraps the server teacher. On-device NN realistically needs an
   **ESP32-S3** (a plain ESP32 has no SIMD → student stays server-side).
2. **Earn-it-first.** Most of this workstream is **post-Gate 3** — you do not quantize
   or write custom kernels for a model that loses to the GRU. The two early-runnable
   items are the **scaling study** (after Gate 1 + GRU) and the **serving-harness
   scaffold** (benchmarks whatever is behind it).

| Deliverable | Artifact (a number) | When |
|---|---|---|
| int8→int4 quantization (student) | quality × latency × **energy (mJ/inf)** curve on ESP32-S3 | post-Gate 3 |
| Fused ODE-step + encoder kernel | measured Triton (GPU) + MCU speedup — the `ragged_dot` analog | post-Gate 3 |
| Teacher→student distillation | teacher-size → student-quality Pareto (incl. latent-trajectory match) | post-Gate 3 |
| Streaming serving stack | p50/p99 + throughput harness; hidden-state-carry (KV-cache analog) | scaffold early; carry post-student |
| Inference co-design sweep | quality × latency × memory frontier; justified operating point | finalise post-Gate 3 |
| One merged upstream PR | merged PR (torchdiffeq / ExecuTorch / TFLite-Micro / LeJEPA) | standing policy |
| Mini scaling study | model × data → held-out-error grid; data- vs capacity-bound | early (after Gate 1 + GRU) |

New gate (detail in PART J): **Gate 7 — Edge viability.** Distilled int8/int4 student
within Δ accuracy of the teacher at the device's ms/energy budget, or conclude
on-device is infeasible and ship streaming server-side. **The FNR = 0.000 safety floor
applies to whichever artifact touches disposition** — the MCU does not buy an accuracy
discount on the LOF class.
